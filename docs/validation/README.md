## Run the review tools

```bash
npm run test:visual:review
npm run review:translations
npm run generate:github-preview
npm run test:e2e:localization-review
```

Open `playwright-report/manual-comparison.html` and `playwright-report/translations/index.html`.
These are generated local artifacts, not pages deployed to paint.rip. They can be opened directly
in a browser. Translation sheets are self-contained apart from their index link and the live-editor
link, so a single locale HTML file can be shared with its reviewer. Export the JSON before closing,
especially if the browser disallows storage on local files.

The visual gallery now combines `tests/visual/pinta-reference/` with supplemental
`tests/visual/native-dialog-references/`, preferring the main capture on duplicate filenames.
At this revision that pairs **112 of 194** web PNGs. The other 82 include web-only, localized,
tool-output and marketing states; they are not automatically 82 missing native features.
Search, category filtering, source paths and actual-pixel viewing support manual inspection.
No native screenshot is approved or regenerated by building this report.

The initial 15-pair review used stored native/Linux evidence. On 5 September Docker was started
and native capture reruns wrote six adjustment PNGs and 11 core PNGs into
`playwright-report/native-fresh/`, without replacing approved references. The core batch failed
while accessing Keyboard Shortcuts; it is **partial**, not a successful native sweep. See the
findings for cached-build provenance and the fresh Layer Properties/Curves confirmation.

The localization review test opens each of the 25 locales, captures the workspace and the
Add-in Manager at desktop and 390-pixel phone widths, checks translated controls and dialog fit,
then exercises Done. The Playwright report contains the screenshots for fluent reviewers; these
are context captures, not new approved pixel baselines. It also tests gallery proportions and
translation-review JSON export. Layout checks do not certify wording or real-device touch.

## Fluent translation review

The queue is `cs`, `el`, `en-CA`, `en-GB`, `es`, `eu`, `ga`, `hr`, `id`, `it`, `kk`, `ko`,
`nl`, `pl`, `pt`, `pt-BR`, `ru`, `sl`, `sv`, `ta`, `tr`, `uk`, `vi`, `zh-CN`, `zh-TW`.
Each has 98 web-only strings. French, German, Arabic and Hebrew retain their previous review
status; this pass does not independently re-certify them or the upstream gettext catalogs.

1. A fluent reviewer opens their sheet and the localized editor. Check meaning, idiom, terminology,
   dangerous recovery/save instructions, number ordering and truncation in the UI.
2. Mark each entry Accept, Needs correction, or Need more context. Include replacement wording
   and rationale for corrections. Do not translate package names just to make everything differ
   from English. The English regional catalogs legitimately share many strings with the source.
3. Export the JSON with reviewer name and fluency/context confirmation. Its SHA-256 binds it to
   the exact source, translation and context reviewed; an edited catalog needs a new review.
4. A maintainer checks the digest, incorporates accepted corrections in
   `scripts/i18n-web-overrides.mjs`, regenerates with `npm run i18n:sync`, runs `npm run verify:i18n`,
   and checks the affected UI. Do not hand-edit generated `src/i18n/locales/*.json`.
5. Record reviewer, date, locale, digest and evidence here before changing that locale's review
   status. The sheet's “submitted-for-maintainer-review” is not automatic approval.

No new fluent-review submissions have been received. Key completeness, generated sheets and
automated checks cannot establish fluency. In particular, assembled storage fragments must be
read as a whole sentence: the example's **120 MB is used; 1 GB is the quota**, not the reverse.

The first browser pass exposed a terminology-review candidate: Czech's native menu command is
“Manažer Pluginů”, while the web-only dialog title is “Správce doplňků”. The Greek menu/title also
use different forms. This is not a missing command; an early test incorrectly assumed their
wording matched. Each review sheet now includes the actual upstream menu wording beside the
dialog-title entry, so a fluent reviewer can decide whether to harmonize them.

## GitHub preview

The preview photographs a local HTML layout around the authentic Cosmic Garden editor capture;
the editor UI is not invented. It preserves the screenshot's aspect ratio and credits the web port.
Its source is `web-assets/social/github-preview.html`; regeneration requires the installed
Playwright Chromium browser, but no running site. The existing website Open Graph image is unchanged.

[GitHub's guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview)
recommends 1280×640 and a file under 1 MB. Upload `web-assets/social/github-preview.png` through
[repository settings](https://github.com/evgenyvinnik/pinta-online/settings), under Social preview →
Edit → Upload an image. Creating or committing the PNG does not set the GitHub repository image.
